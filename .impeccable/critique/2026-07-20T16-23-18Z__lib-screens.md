## Anti-Patterns Verdict

This is **not generic AI slop.** The Khaki/green/orange "Sunlit Trade Stall" system has a real point of view — cushioned cards on cream, one hero figure per screen, money coloured by meaning. A category-fluent user would find the *look* trustworthy.

The failure mode is different and more specific: **template drift + underbuilt trust.** The screens still carry the imported mockup's USD amounts and Australian content, and the interactions that would make a stranger hand over money (people, status, escrow, verification) aren't built yet. So the surface looks finished while the substance — the thing DESIGN.md calls "Trust is the interface" — is missing.

Deterministic scan: N/A (native Flutter; the HTML/CSS detector doesn't parse Dart). Findings below are verified against DESIGN.md and CLAUDE.md as the contract.

## What's Working

1. **The elevation + spacing language is executed well.** `GwCard`, the soft-shadow tokens, 22px radii, and generous whitespace deliver the "cushioned, never the classifieds wall" feel. This is the hardest part to get right and it's right.
2. **Money colour-by-meaning is mostly correct.** Wallet gets it: positive amounts green, fees/withdrawals neutral ink (never red), balance card green. `AppText.price` defaults green. The Green Money Rule is respected where it counts.
3. **One hero figure per screen holds.** `24 Gigs` on Home, the balance on Wallet — the Big-Number Rule isn't diluted into a dashboard.

## Priority Issues

### [P1] The entire app is priced in US Dollars
**Why it matters:** CLAUDE.md Rule 5 and DESIGN.md's Don'ts are unambiguous — "The symbol is `R`, prefixed. No other currency symbol appears anywhere." There are **29 `$` occurrences across 7 screens** (`$1,978.85`, `$410 earned`, `$65 fixed`, `-$4.20`…). The comma-grouped format (`$1,978.85`) is also wrong for SA, which groups with spaces (`R1 978`). For an audience whose trust you're trying to earn, foreign money is an immediate "this isn't for me" signal, and there's no shared formatter to fix it in one place.
**Fix:** Add the `*ZarMinor` integer-minor-unit formatter CLAUDE.md specifies (`R1 250`, `R450`, `R37.50`), route every amount through it, and replace all fixtures.
**Suggested command:** `/impeccable clarify`

### [P1] Trust is not yet the interface — the gig rows are the wall you're designing against
**Why it matters:** This is the product's first design principle and its whole reason to exist. DESIGN.md: "If a list has no named humans, no status, and no breathing room, it is that wall." The Home and Browse gig rows are exactly that — khaki thumbnail + title + distance + price, **no poster, no rating, no verification badge, no lifecycle status.** Nowhere in the app is escrow or the verification badge surfaced (Gig Detail shows a name + rating but nothing that says "your money is protected"). The breathing room is there; the trust cues aren't.
**Fix:** Put a named human on every gig row (initials avatar + name + `★` rating), add a lifecycle status pill, and surface an escrow/"protected payout" cue on Gig Detail and the payout card. This is the difference between Daala and OLX.
**Suggested command:** `/impeccable shape` (rework the gig-row and gig-detail trust model), then `/impeccable layout`

### [P1] The Readable-Muted Rule is broken at the token level and in 20 screen spots
**Why it matters:** DESIGN.md §2 makes this a named, deliberate correction: muted text bottoms out at **ink-55%**, "anything fainter is not text," and it explicitly says the mockup's **ink-35% placeholder "is not to be reproduced."** Yet `AppText.meta` is `ink45` and `AppText.overline` is `ink50` in the theme itself, `browse_screen.dart:73` uses the exact banned **ink35** search placeholder, and there are **20 sub-ink55 text usages across all 9 screens**. This fails hardest in precisely the bright-daylight, varied-literacy conditions the product ships into.
**Fix:** Lift `AppText.meta`/`overline` to `ink55` in the theme, delete every `ink50/45/40/35` on *text* in screens, and carry any remaining hierarchy with size/weight (which this system has in abundance).
**Suggested command:** `/impeccable typeset`

### [P1] Primary actions are inert and every tap is silent
**Why it matters:** `buildAppTheme()` sets `NoSplash.splashFactory` + transparent highlight, and every control is a bare `GestureDetector` — so **nothing gives pressed feedback** (Nielsen #1). Worse, the loudest elements on their screens do nothing: **Apply Now, Post Gig, Withdraw to Bank have no `onTap`**, the Browse search field is a static `Container`, and **Inbox rows have zero `onTap`** — you cannot open a conversation, which is the Inbox's only job. DESIGN.md specs a pressed state (scale 0.97, drop shadow) for exactly this reason. "Looks like it works, doesn't" is the fastest way to lose the trust you built visually.
**Fix:** Wrap interactive primitives in a pressed-state widget (0.97 scale, shadow step-down, 120ms), give the Inbox row an `onTap` to a thread route, and stub the CTAs to navigate even in skeleton phase.
**Suggested command:** `/impeccable harden`

### [P2] Imported-template content leaks the wrong country and the wrong brand
**Why it matters:** DESIGN.md: "Don't carry the reference mockup's placeholder content into real screens." Five leaks remain — `within 5km of Fitzroy` (Home), `Fitzroy VIC 3065` (Gig Detail), `around Fitzroy` (Profile bio), **`Groundwork Support`** (Inbox — the old project name), and the theme docstring still calls it the "Groundwork" marketplace. The product is Daala, in South Africa.
**Fix:** Swap to SA suburbs/cities (`Braamfontein 2001`, `within 5km of Melville`), rename to Daala, and scrub "Groundwork" from code + copy.
**Suggested command:** `/impeccable clarify`

## Persona Red Flags

**Casey (Distracted Mobile — the core Daala user, entry-level Android, one-handed, bright daylight):** Taps Apply Now → nothing happens, no ripple, no navigation; can't tell if the tap registered. Tries to read `1.2km · posted 2h ago` at ink45 in sunlight and can't. Filter chips are 34px tall — below the 48dp Android target, hard to hit one-handed. This persona *is* the brief, and three of the top issues hit them first.

**Jordan (First-Timer):** Sees `$65` and `Fitzroy VIC` and quietly wonders if this app is even for South Africa. Reaches Gig Detail ready to commit money to a stranger and finds no "your payment is protected" reassurance — no escrow cue, no verification badge. Header buttons are icon-only (search, tune, bell, wallet) with no labels; hesitates on each.

**Sam (Accessibility):** Icon-only buttons have no `Semantics` labels, so a screen reader announces nothing actionable. Unread status is a 9px orange dot — colour/size alone. White-on-orange CTA text (`Apply Now`, `Withdraw to Bank`) computes to ~2.5:1, below even the 3:1 large-text floor — this is per the brand spec, but it's the audience's worst-case (glare) so it's worth a design decision, not a silent pass.

## Minor Observations

- **Token scale erosion.** Screens constantly do `AppText.metaStrong.copyWith(fontSize: …, fontWeight: …)`. Root cause: the theme is missing DESIGN.md roles (`figure` 22/w800, `value` 14/w600, `title` 15/w700, `caption`, `status` 11/w700). Add the roles; stop patching — this is The Complete-Scale Rule.
- **Emoji as iconography** (🗓️ 📍 👥 💰 💳) mixed with the Material outline set violates "one icon family throughout" and native slop guidance; emoji also ignore your colour tokens and render differently per OS.
- **No loading / empty / error states** anywhere — DESIGN.md §5 explicitly says every list "still owes three more." Expected gap for a skeleton, but it's the next layer.
- **Booking sheet:** `Done` is hardcoded `ink30` and never turns green when toggles change (spec: ink-40 → green when dirty); no swipe-down dismiss or grabber handle.
- **`StatusBar` widget** hardcodes a fake `9:41` iOS status bar — pure mockup residue; the OS draws this on device.
- **IA nuance:** "Browse" exists twice — the Home toggle shows categories inline while the search icon pushes `/browse`; two different browse surfaces may confuse.

## Questions to Consider

- What would Gig Detail look like if the *first* thing a nervous first-timer saw was "R65 held in escrow until the work's done" rather than the payout figure?
- If every gig row led with a face and a rating, would you still need the khaki photo placeholder at all?
- The visual system is confident. What's the one interaction that, when it finally responds to a tap, makes the app feel as solid as it looks?
